# AuditLens 탐지 규칙과 분석 로직

> 이 문서는 2026-11-06 main(`3cf55d6`)의 실제 코드(`auditlens/detection.py`, `auditlens/validation.py`, `auditlens/analysis.py`)를 기준으로 썼습니다. 설계 당시 기록은 [설계서](설계서.md)에 있으며, 설계서와 코드가 다른 부분은 맨 아래 7절에 정리했습니다.
>
> AuditLens의 탐지 결과는 **검토 대상 거래(검토 후보)** 입니다. 부정이나 오류를 확정하지 않으며, 탐지되지 않은 거래가 정상이라는 뜻도 아닙니다.

## 1. 전체 처리 흐름

```
파일 읽기 → 열 연결 → 데이터 검증(V1~V12) → 분석용 표 준비 → 기초 분석
                                                         ↘ 탐지 규칙 R1~R6 → 전표별 종합 → 결과 다운로드
```

| 단계 | 하는 일 | 코드 |
| --- | --- | --- |
| 1. 파일 읽기 | CSV(UTF-8·CP949)와 Excel(.xlsx, .xlsm)을 읽습니다. 값은 바꾸지 않고 글자 그대로 읽습니다. | `loader.py` |
| 2. 열 연결 | 파일의 열 이름을 표준 열(전표번호, 회계처리일 등)에 자동으로 짝지어 보여 주고, 사용자가 확인·수정합니다. 금액은 차변·대변 두 열 형식과 금액 한 열 + 차대 구분 열 형식을 받습니다. | `schema.py` |
| 3. 데이터 검증 | V1~V12 항목을 검사해 오류·경고·정보로 알립니다. 오류가 있으면 분석을 시작하지 않습니다. 날짜·금액을 읽을 수 없거나 필수 값이 빈 행은 분석에서 제외하고 행 번호와 사유를 보여 줍니다. | `validation.py`, `formats.py` |
| 4. 분석용 표 준비 | 결산월을 기준으로 회계연도와 회계연도 안의 월 순서를 계산합니다. | `analysis.prepare` |
| 5. 기초 분석 | 전표 현황, 차변·대변 일치, 계정별 분석, 월별 추이, 전기·당기 같은 달 비교. 탐지 결과가 아닙니다. | `analysis.py` |
| 6. 탐지 | R1~R6을 계산하고 전표 단위로 모읍니다. | `detection.py` |
| 7. 다운로드 | 화면과 같은 결과를 Excel(15개 시트) 또는 CSV 묶음(ZIP)으로 만듭니다. 다시 계산하지 않습니다. | `export.py` |

### 입력 열

| 구분 | 열 | 쓰이는 곳 |
| --- | --- | --- |
| 필수 | 전표번호, 회계처리일, 계정코드, 계정과목명, 차변금액, 대변금액 | 모든 분석과 규칙 |
| 선택 | 입력일시 | R3(b) 결산 후 입력, R3(c) 주말 입력 |
| 선택 | 거래처 | R2(a), R5, R6 |
| 선택 | 전표 원천, 전표 유형 | R4(a) |
| 선택 | 입력자, 승인자 | R4(b), R4(c) |
| 선택 | 적요 | R4(d), R6 적요 일치 표시 |

선택 열이 없으면 그 열이 필요한 규칙이나 세부 조건은 **검사하지 않고**, 화면에 검사하지 않았다고 표시합니다.

## 3. 공통 기준

- **라인 금액** = 차변 + 대변(원). **방향**은 차변 금액이 있으면 '차변', 아니면 '대변'입니다.
- **0원·음수·차대 동시 기재 라인**은 로그나 중앙값 비교에 쓸 수 없어 R1·R2(a) 비교에서 빼고, 금액을 바꾸지 않은 채 사유와 함께 '비교 제외 라인'으로 따로 보여 줍니다. R6은 0원 라인과 차대 동시 기재 라인, 거래처가 빈 라인을 비교하지 않습니다.
- 분석에서 **제외된 행**(3단계 검증에서 날짜·금액을 읽을 수 없거나 필수 값이 빈 행)은 기초 분석과 모든 규칙에 들어가지 않습니다. 모든 행이 제외되면 오류로 멈춥니다.
- 계정은 **계정코드**로 구분합니다. 특정 업종의 계정 체계를 가정하지 않습니다.
- **결산일**은 사이드바에서 정합니다(기본 12월 31일). 회계연도와 R3·R4(c)에 함께 쓰입니다.
- 모든 수치 기준은 **조정 가능한 기본값**입니다. 감사기준서가 정한 값이 아닙니다. 사이드바 '탐지 기준 설정'에서 규칙별로 켜고 끄거나 값을 바꿀 수 있고, 바꾼 항목은 화면 5-3과 다운로드 '적용 기준' 시트에 남습니다.
- 모든 탐지 결과에는 **탐지 이유와 판단 근거**(비교 대상, 기준값, 실제 값)를 함께 표시합니다. 점수나 위험 등급은 만들지 않습니다.

## 4. 규칙별 로직

### R1. 계정별 금액 분포 이탈 (분개 라인 단위)

- **목적**: 같은 금액이라도 계정마다 평범한 정도가 다르므로, 금액 자체가 아니라 '그 계정에서 드문 금액'을 찾습니다.
- **계산**: 같은 계정코드·같은 방향 라인의 금액에 log10을 취해 1사분위수(Q1)와 3사분위수(Q3)를 구합니다. IQR = Q3 − Q1. 라인 금액이 **10^(Q3 + 배수 × IQR)을 넘으면** 검토 대상입니다.
- **기본값**: 배수 3.0, 계정·방향별 최소 라인 30건(미만이면 검사하지 않고 '검사하지 않은 계정·방향'으로 표시).
- **로그를 쓰는 이유**: 회계 금액은 오른쪽 꼬리가 긴 분포라 원금액 그대로 IQR을 쓰면 큰 정상 거래 때문에 기준이 지나치게 넓어집니다.
- **판단 근거 표시**: 비교 라인 수, 계정 중앙값, 상한 금액, 이 라인 금액.
- **예시(제조업 샘플)**: 소모품비 차변 46,800,000원 1건(이 계정의 보통 금액은 수십만 원대).
- **한계**: 연 1회 성과급·설비 취득처럼 원래 크고 드문 정상 거래도 탐지될 수 있습니다. 한 계정에 성격이 다른 거래가 섞이면 기준이 넓어져 놓칠 수 있습니다. 상한만 보며 작은 금액은 보지 않습니다.

### R2(a). 거래처 이전 거래 대비 이례적 금액 (분개 라인 단위)

- **목적**: 이 거래처와 평소 하던 거래보다 훨씬 큰 금액을 찾습니다. R1이 계정 전체와 비교한다면 R2(a)는 거래처별로 비교합니다.
- **계산**: 같은 거래처·계정·방향에서 이 라인보다 회계처리일이 **앞선** 거래(같은 날 거래 제외)가 최소 건수 이상이고, 금액이 **그 중앙값 × 배수를 초과**하면 검토 대상입니다.
- **기본값**: 배수 5.0, 최소 이전 거래 5건.
- **판단 근거 표시**: 이전 거래 수, 이전 거래 중앙값, 배수.
- **한계**: '과거'는 올린 파일 안의 앞선 거래뿐입니다. 거래처명 표기가 다르면 다른 거래처로 봅니다. 거래처가 빈 라인과 이전 거래가 부족한 라인은 비교하지 않고 건수를 '처리 현황'에 표시합니다.

### R2(b). 계정별 월 건수·금액 이상 기간 (계정-월 단위, 개별 거래가 아님)

- **목적**: 특정 달에 거래가 몰리거나 빠진 계정을 찾습니다.
- **계산**: 계정별로 월 라인 수와 월 금액을 구하고(거래가 없는 달은 0), 같은 계정 **다른 모든 달**의 중앙값과 비교합니다. 상한 배수 이상이면 급증, 하한 배수 이하이면 급감입니다.
- **기본값**: 상한 3.0배, 하한 1/3배(화면에는 0.33으로 보이며 내부 값은 정확히 1/3).
- **표시**: 판정은 '검토 대상 기간 (계정-월)'이며 화면 5-2에 따로 보여 줍니다. 한 계정-월이 건수와 금액 두 항목에 모두 해당하면 2행이 됩니다. **전표별 종합에는 넣지 않습니다.** '그 달의 거래 보기'로 해당 기간의 전표를 찾아볼 수 있습니다.
- **한계**: 계절성(연말 매출 증가 등)을 구분하지 못합니다. 파일이 월 중간에 시작·끝나면 그 달이 적게 보일 수 있습니다. 다른 달 중앙값이 0이면 비교하지 않습니다.

### R3. 기말·결산 전후 및 비정상 시점 분개 (전표 단위)

| 세부 조건 | 내용 | 기본값 |
| --- | --- | --- |
| (a) 결산일 전후 | 회계처리일이 결산일 전후 n영업일 이내 | n = 3, 켜짐 |
| (a-2) 매월 말일 전후 | 매월 말일 전후 n영업일 이내(결산일과 같은 말일은 (a)로 봄) | 보조 옵션, 꺼짐 |
| (b) 결산 후 입력 | 회계처리일은 결산일 이전인데 입력일시가 결산일 다음 날 이후 | 입력일시 필요 |
| (c) 주말 입력 | 입력일시가 토·일요일 | 입력일시 필요 |

- **목적**: 기말·결산 후 분개는 실적을 맞추려는 조정이 들어갈 수 있는 시점이고, 주말 입력은 평소 통제 흐름 밖일 수 있습니다.
- **판단 근거 표시**: 해당 조건, 결산일, 입력일시. 화면에 조건별 전표 수와 (a-2)를 켰을 때 추가될 전표 수를 함께 보여 줍니다.
- **한계**: 기말에는 감가상각·충당금 같은 정상 결산 분개가 몰립니다. 영업일은 월~금이며 공휴일은 반영하지 않습니다. 자동 배치 전표는 주말에도 정상적으로 생길 수 있습니다.

### R4. 수기·조정 분개와 특정 조건 (전표 단위)

| 세부 조건 | 내용 | 기본값 |
| --- | --- | --- |
| (a) 수기·조정 | 전표 원천 또는 전표 유형이 사용자가 고른 값 | 원천 '수기', 유형 '조정'·'결산' |
| (b) 입력자 = 승인자 | 입력자와 승인자가 같음 | — |
| (c) 드문 입력자 | 그 회계연도 입력자 전표 수 ÷ 전체 전표 수가 기준 미만 | 1% |
| (d) 적요 | 모든 라인의 적요가 비었거나 키워드 포함 | 수정, 조정, 오류, 임시 |

- **목적**: 자동 전표는 시스템 통제를 거치지만 수기·조정 분개는 사람의 판단이 개입하고, 직무 분리가 안 된 전표는 검토 필요성이 높습니다.
- **보조 목록**: 수기·조정 여부(a) **하나만** 해당하는 전표는 종합에서 '보조 (수기·조정 여부만 해당)'로 나누고 판정 문구를 '수기·조정 전표(보조 정보)'로 씁니다. 수기 전표라는 사실만으로는 오류·부정을 뜻하지 않기 때문입니다.
- **한계**: '수기'를 나타내는 값은 ERP마다 달라 사용자가 골라야 합니다. 작은 회사는 입력자와 승인자가 같은 것이 일상일 수 있습니다. 적요 열 값이 모두 비어 있으면 (d)는 '평가 불가'로 두고 탐지하지 않습니다.

### R5. 신규 거래처·신규 계정 조합 (거래처 또는 거래처×계정 단위)

- **목적**: 기말에 갑자기 나타나 큰 금액을 거래한 거래처는 실재성·특수관계자 여부를 확인할 필요가 있을 수 있습니다.
- **계산**: 파일 안에서 거래처의 최초 등장일이 분석 기간 **마지막 n개월** 안이고, 합계 금액이 **기준금액 이상**이면 검토 대상입니다. 합계는 전표마다 한 번만 셉니다(그 거래처 라인의 차변 합계와 대변 합계 중 큰 값). 기존 거래처가 처음 쓰는 계정 조합도 같은 방식으로 봅니다.
- **기본값**: 마지막 2개월. **기준금액은 기본값이 없습니다.** 감사인이 중요성 판단에 따라 입력해야 검사합니다.
- **한계**: '신규'는 올린 파일 기준입니다. 거래처 마스터가 없어 표기 차이가 오탐을 만듭니다.

### R6. 중복 가능 분개 (전표 쌍 단위)

- **목적**: 같은 증빙의 이중 입력은 비용·매출 과대계상이나 이중 지급으로 이어질 수 있습니다.
- **계산**: 서로 다른 전표에 계정·거래처·방향·금액이 같은 라인이 있고 회계처리일 차이가 n일(달력 기준) 이내면 검토 대상입니다. 적요가 있으면 적요 일치 여부를 함께 표시합니다.
- **기본값**: 7일.
- **한계**: 같은 금액의 정상 반복 거래(주간 용역비 등)가 걸릴 수 있습니다. 금액을 조금 바꾼 중복이나 다른 거래처명으로 입력한 중복은 놓칩니다.

## 5. 전표별 종합

R1·R2(a)·R3·R4·R5·R6의 결과를 전표 단위로 모읍니다(R2(b)는 기간 판단이라 넣지 않음).

1. 전표마다 해당 규칙과 세부 조건(예: R3(a), R4(b))을 모읍니다.
2. 해당 세부 조건이 **R4(a) 하나뿐**이면 보조 목록, 그 밖에는 우선 검토 목록입니다.
3. 정렬: 우선 검토 목록 먼저 → 해당 규칙 수가 많은 순 → 해당 세부 조건 수가 많은 순 → 회계처리일.
4. **점수나 가중치는 만들지 않습니다.** 규칙 사이의 중요도는 감사인이 판단할 몫이기 때문입니다.

'탐지 사유' 표에는 한 전표가 여러 규칙·여러 라인에서 탐지된 사유가 모두 한 행씩 들어갑니다.

## 6. 결과 다운로드

Excel 15개 시트: 안내, 적용 기준, 우선 검토, 보조 목록, 탐지 사유, R1, R2(a), R2(b) 이상 기간, R3, R4, R5, R6, 비교 제외 라인, 검토 대상 전표 라인, 검증 결과. CSV 묶음(ZIP)에는 안내 txt와 나머지 시트별 CSV 14개가 들어갑니다. 첫 장 '안내'에 판정의 뜻과 한계, 원본 파일 이름, 적용 기준을 적고, `=`·`+`·`-`·`@`로 시작하는 글자 값 앞에는 작은따옴표를 붙여 Excel 수식으로 실행되지 않게 합니다.

## 8. 감사기준과의 관계

설계서에서 감사기준서 240(부정 관련 감사인의 책임)과 330(평가된 위험에 대한 대응)이 분개 테스트의 필요성과 고려할 특성을 다룬다고 적었습니다. 다만 **해당 문단 번호와 문구는 원문으로 확인하지 않았습니다(미확인)**. 그래서 이 문서와 화면은 기준서 문구를 인용하지 않습니다. 기준서는 구체적인 임계값(예: IQR 몇 배)을 정하지 않으므로, 이 프로그램의 수치는 모두 조정 가능한 기본값입니다.
