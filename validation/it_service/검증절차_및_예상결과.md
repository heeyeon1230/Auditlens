# 4단계 검증 1: IT 서비스업 가상 분개장

> 이 폴더의 모든 데이터는 프로그램으로 만든 가상 데이터입니다. 회사(가상클라우드솔루션(주)), 거래처, 입력자 ID는 실제와 관계없습니다.
> 일부 전표는 탐지 규칙 검증을 위해 일부러 넣은 패턴이며, 부정이나 회계 오류를 뜻하지 않습니다.

## 1. 목적과 범위

제조업 가상 데이터로 만든 AuditLens가 거래 구조가 다른 IT 서비스업 분개장에서도 R1~R6가 설계대로 작동하는지 확인합니다.
원재료·재공품·제품·제조원가 계정은 쓰지 않았습니다.

- 기준 코드: main `51dc27e` (PR #8 병합 후). 애플리케이션 코드(`auditlens/`, `app.py`)는 바꾸지 않았습니다.
- 정답표(`ground_truth/`)는 업로드 파일(`upload/`)과 다른 폴더에 있습니다. **프로그램에는 `upload/`의 파일만 올립니다.**
- 이 문서의 '예상 결과'는 아래 2절의 코드 조건으로 데이터를 설계하면서 적은 것입니다. 7절에 설계 조건을 확인하려고 실행한 범위를 따로 적었습니다.

## 2. 코드 기준 R1~R6 탐지 조건과 기본값

`auditlens/detection.py`의 `DetectionSettings` 기본값과 각 함수의 실제 조건입니다.

| 규칙 | 단위 | 실제 조건 (코드) | 기본값 | 전제조건 |
| --- | --- | --- | --- | --- |
| R1 | 분개 라인 | 같은 계정코드·같은 방향 라인의 log10 금액으로 Q1·Q3를 구하고, 금액 > 10^(Q3 + 배수 × IQR) | 배수 3.0 | 계정·방향별 라인 30건 이상. 0원·음수·차대 동시 기재 라인은 비교에서 빼고 따로 표시 |
| R2(a) | 분개 라인 | 같은 거래처·계정·방향에서 회계처리일이 **더 이른** 거래(같은 날 제외)의 중앙값 × 배수를 **초과** | 배수 5.0 | 이전 거래 5건 이상. 거래처 빈 라인, 금액 문제 라인은 비교하지 않음 |
| R2(b) | 계정-월 (기간) | 계정별 월 라인 수 또는 월 금액(차변+대변 라인 금액 합)이 같은 계정 **다른 모든 달** 중앙값의 상한 배수 이상(급증) 또는 하한 배수 이하(급감) | 상한 3.0, 하한 1/3 | 파일의 첫 달~마지막 달, 거래 없는 달은 0. 다른 달 중앙값이 0이면 비교하지 않음. 2개월 미만이면 검사 안 함. 종합(전표별)에 넣지 않음 |
| R3 | 전표 | (a) 회계처리일(전표의 가장 이른 날)이 직전·직후 결산일 전후 n영업일 이내 / (a-2) 매월 말일 전후(보조 옵션) / (b) 입력일시 날짜 > 그 회계연도 결산일 / (c) 입력일시가 토·일 | n = 3, (a-2) 꺼짐, 결산일 12-31 | 영업일은 월~금, 공휴일 미반영. 입력일시(전표의 가장 늦은 값)가 없으면 (b)(c) 검사 안 함 |
| R4 | 전표 | (a) 원천 또는 유형이 선택 값 / (b) 입력자와 승인자가 같음 / (c) 그 회계연도 입력자 전표 수 ÷ 전체 전표 수 < 기준 / (d) 모든 라인 적요가 빔 또는 키워드 포함 | 원천 '수기', 유형 '조정'·'결산', 기준 1%, 키워드 수정·조정·오류·임시 | 열이 없으면 그 조건은 검사 안 함. 적요 열 값이 모두 비면 (d) 평가 불가. (a)만 해당하는 전표는 종합의 보조 목록 |
| R5 | 거래처 / 거래처×계정 | 파일 내 최초 등장일이 마지막 n개월(마지막 달 포함, 달 단위) 안이고 합계 ≥ 기준금액. 신규 거래처 합계는 전표마다 max(차변 합, 대변 합), 신규 계정 조합은 그 조합 라인 금액 합 | n = 2, **기준금액 기본값 없음** | 기준금액을 입력해야 탐지. 거래처 빈 라인 제외 |
| R6 | 전표 쌍 | 서로 다른 전표에 계정·거래처·**방향**·금액이 같은 라인이 있고 회계처리일 차이 ≤ n일(달력) | n = 7 | 거래처 빈 라인, 0원 라인, 차대 동시 기재 라인은 비교하지 않음. 적요 일치 여부만 표시 |
| 종합 | 전표 | R1·R2(a)·R3·R4·R5·R6 사유를 전표별로 모음. 우선 검토 → 해당 규칙 수 → 해당 세부 조건 수 순서 | 점수·가중치 없음 | R2(b)는 넣지 않음 |

### 설계서(`docs/설계서.md`)와 실제 코드의 차이

검증은 실제 코드를 기준으로 했습니다.

| 항목 | 설계서 | 실제 코드 |
| --- | --- | --- |
| R2(a) 비교 묶음 | 거래처·계정 조합 | 거래처·계정·**방향**. '이전'은 회계처리일이 더 이른 거래(같은 날 제외), 기준은 '초과' |
| R2(b) 표시 위치 | 기초 분석 화면의 계정-월 표 | 5-2절 '검토 대상 기간 (계정-월)'으로 따로 표시. 비교 대상은 파일 전체(2년)의 다른 모든 달이며 전기 동월 비교가 아님 |
| R3(a) | 월말 **또는** 결산일 전후 3영업일 | 기본은 결산일만. 월말은 (a-2) 보조 옵션이며 기본 꺼짐 |
| 입력일시가 없을 때 | 5절 표: posting_date로 대체 | 대체하지 않고 (b)(c)를 검사하지 않음 |
| R4(c) '연간' | 연간 전표 수 | 결산월·결산일 기준 회계연도별 |
| R4 종합 처리 | 규칙 수로 정렬 | (a)만 해당하는 전표는 '보조 (수기·조정 여부만 해당)' 목록으로 분리 |
| R4(d) | 적요 없음·키워드 | 적요 열 값이 모두 비면 '평가 불가'(PR #8) |
| R5 단위 | 라인 | 거래처 또는 기존 거래처×계정 단위, 해당 전표를 함께 표시. 기준금액 기본값 없음 |
| R6 조건 | 같은 계정·거래처·금액 | 같은 **방향**도 조건. 결과는 전표 쌍 단위 |

## 5. 검증 절차

1. `streamlit run app.py` → '내 파일 업로드'에서 `upload/가상IT_분개장_2024_2025.csv`를 올립니다.
2. 열 연결: 13개 열이 모두 자동 연결되는지 확인합니다(금액 형식 '차변·대변 두 열').
3. 검증 결과: 오류·경고 없이 V10 정보 1건(2024-01-08 ~ 2025-12-31, 24개월, 차대 합계 9,508,434,100원)만 나오는지 확인합니다.
4. 사이드바 '공통: 결산일'은 기본값 12월 31일 그대로 둡니다.
5. 탐지 기준은 모두 기본값으로 두고, **R5 기준금액만 20,000,000원**을 입력합니다. 이 값은 검증용 입력값이며 권장값이 아닙니다.
6. 5절 각 탭과 종합 화면을 정답표의 '대상'·'예상 결과'와 대조합니다. 탐지되지 않아야 할 사례도 해당 탭에 없는지 확인합니다.
7. 결과 다운로드(Excel·CSV ZIP)를 받아 시트별 건수가 화면과 같은지 확인합니다.
8. 같은 순서로 `.xlsx` 파일을 올려 결과가 1~7과 같은지 확인합니다.
9. 단일 금액 파일은 금액 형식 '금액 한 열 + 차대 구분 열'을 고르고, '금액'·'차대구분' 열을 연결한 뒤 '차' → 차변, '대' → 대변으로 지정합니다. 결과가 1~7과 같은지 확인합니다.

## 6. 규칙별 사례와 예상 결과

전표번호는 정답표의 '대상' 열과 같습니다. 금액 비교의 대략적인 기준값(상한, 중앙값)은 설계 때 추정한 값이며 7절에서 확인했습니다.

## 7. 설계 조건 확인을 위한 실행 범위

데이터가 위 전제조건(최소 건수, 이전 거래 수, 월별 비교 등)을 실제로 충족하는지 확인하려고, 화면 대신 앱이 쓰는 함수를 직접 실행했습니다.
`loader.read_uploaded_file` → `schema.suggest_mapping`(단일 금액 파일은 `suggest_single_amount` + '차'/'대' 지정) → `validation.validate_journal` → `analysis.prepare(결산월 12)` → `detection.run_detection(기본값, R5 기준금액 20,000,000원)`.

- 세 파일 모두 13개 열이 자동 연결되었고, 검증 결과는 V10 정보 1건뿐이었으며 2,708행이 모두 분석에 들어갔습니다.
- CSV 결과가 6절 요약표와 모든 건수·전표번호에서 같았습니다. 예상하지 않은 탐지는 없었습니다.
- Excel 파일과 단일 금액 파일의 R1~R6·종합 결과 표가 CSV 결과와 같았습니다.
- 확인한 기준값: 835 차변 상한 40,595,780원(중앙값 7,290,000원, 147라인), R2(a) 사례 이전 거래 중앙값 7,101,000~7,237,500원, 831 2025-07 다른 달 중앙값 1,751,600원.

**아직 하지 않은 것**: Streamlit 화면에서 파일을 올려 보는 검증(5절 1~9), 결과 다운로드 파일 대조. 이 확인은 4단계 다음 작업으로 남아 있습니다.

## 8. 검증상 한계

- 규칙을 아는 상태에서 만든 데이터라, 이번 결과는 '구현이 정한 조건대로 작동하는지'를 보여 줄 뿐 실제 회사 자료에서의 탐지율·오탐률을 뜻하지 않습니다.
- 반복 거래는 일정한 날짜(8~24일 평일)와 좁은 금액 폭으로 만들어 실제 자료보다 깨끗합니다. 공휴일, 부가가치세, 역분개·음수 금액, 차대 동시 기재, 적요 일부 미입력 같은 상황은 이 데이터에 없습니다.
- 결산월은 12월 하나만 다룹니다. 3월·6월 결산 같은 회계연도 일반화는 이 데이터로 확인하지 않습니다.
- 날짜·금액은 표준 표기(YYYY-MM-DD, 쉼표 없는 정수)만 씁니다. PR #8의 다양한 표기 처리는 이 데이터로 확인하지 않습니다.
- R5 기준금액 20,000,000원은 검증을 위한 입력값입니다. 실제 감사에서는 중요성 판단에 따라 정해야 합니다.
- 영업일 계산에 공휴일이 없어 2025-12-25도 영업일로 셉니다. C-R3A-01(12-26)은 공휴일과 관계없이 3영업일이지만, N-R3A-01(12-24)은 공휴일을 빼면 4영업일이 됩니다(어느 쪽이든 기준 밖).
- acct09의 (c) 사례와 acct03의 경계 사례는 사람이 연동 전표를 생성한 것으로 가정해 원천을 '자동'으로 두었습니다. (c)만 따로 보기 위한 설정입니다.
- 반복 수기 전표 94개가 보조 목록에 들어가는 것은 R4(a) 기본값(원천 '수기')에 따른 결과입니다. 수기 비중이 큰 회사에서는 보조 목록이 커집니다.
